# Деплой Replit-проекта на Amvera Cloud

Полная инструкция по подготовке и выгрузке pnpm-монорепозитория (или любого Node.js-проекта) из Replit на Amvera Cloud с Docker-сборкой.

---

## 1. Предварительные требования

### Со стороны пользователя
- Аккаунт на [cloud.amvera.ru](https://cloud.amvera.ru)
- Созданный проект на Amvera (тип: «Приложение»)
- Если нужна БД — создать отдельный сервис PostgreSQL на Amvera

### Запросить у пользователя
- **Логин Amvera** (например: `pdkiller666`)
- **Название проекта** на Amvera (например: `grafik`)
- **Пароль** от аккаунта Amvera (для git push)
- **DATABASE_URL** (если используется БД Amvera) — формат:
  ```
  postgresql://USER:PASSWORD@amvera-ЛОГИН-cnpg-ИМЯ_БД-rw:5432/ИМЯ_БД
  ```

### Важно: переменные окружения на Amvera
Пользователь должен добавить в настройках проекта на Amvera:
- `DATABASE_URL` — строка подключения к PostgreSQL
- `PORT` — порт, на котором слушает приложение (обычно `8080`)
- Любые другие секреты (SMTP-пароли, API-ключи и т.д.)

## 2. Критические нюансы Replit → Amvera

### 2.1. ОБЯЗАТЕЛЬНО: `--no-frozen-lockfile`

В `pnpm-workspace.yaml` Replit добавляет секцию `overrides` с платформо-зависимыми исключениями (esbuild, lightningcss, rollup и др.). Эти overrides оптимизированы под linux-x64 Replit и НЕ совпадают с lockfile при сборке в Docker.

**Ошибка:**
```
ERR_PNPM_LOCKFILE_CONFIG_MISMATCH  Cannot proceed with the frozen installation.
The current "overrides" configuration doesn't match the value found in the lockfile
```

**Решение:** В Dockerfile использовать ТОЛЬКО `--no-frozen-lockfile`:
```dockerfile
RUN pnpm install --no-frozen-lockfile
```

НИКОГДА не использовать `--frozen-lockfile` — это гарантированно сломает сборку.

### 2.2. ОБЯЗАТЕЛЬНО: Копировать tsconfig файлы

Replit-проекты используют `tsconfig.base.json` в корне, на который ссылаются `tsconfig.json` в артефактах через `"extends": "../../tsconfig.base.json"`. Если не скопировать эти файлы в Docker — сборка Vite/TypeScript упадёт.

**Ошибка:**
```
[vite:build-html] failed to resolve "extends":"../../tsconfig.base.json"
```

**Решение:** В каждом build-stage добавлять:
```dockerfile
COPY tsconfig.base.json tsconfig.json ./
```

### 2.3. Раздача фронтенд-статики из бэкенда

На Amvera обычно один контейнер, поэтому API-сервер (Express) должен раздавать собранный фронтенд как статику. В `app.ts` добавить:

```typescript
import path from "path";
import { fileURLToPath } from "url";

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const staticDir = path.resolve(__dirname, "public");

// После всех API-маршрутов:
app.use(express.static(staticDir));
app.get("/{*splat}", (_req, res) => {
  res.sendFile(path.join(staticDir, "index.html"));
});
```

В Dockerfile собранный фронтенд копируется в папку `public` внутри dist бэкенда:
```dockerfile
COPY --from=build-frontend /app/artifacts/FRONTEND/dist/public/ artifacts/api-server/dist/public/
```

### 2.4. PORT — обязательная переменная

Amvera ожидает приложение на определённом порту (обычно `8080`). В Dockerfile:
```dockerfile
ENV PORT=8080
EXPOSE 8080
```

В коде сервера обязательно читать `process.env.PORT`:
```typescript
const port = parseInt(process.env.PORT!, 10);
```

### 2.5. Миграции БД при старте

Если используется Drizzle ORM — миграции запускаются в CMD:
```dockerfile
CMD ["sh", "-c", "cd lib/db && npx drizzle-kit push --config ./drizzle.config.ts --force && cd /app && node artifacts/api-server/dist/index.mjs"]
```

### 2.6. `.dockerignore` — исключить Replit-артефакты

```dockerignore
node_modules
.git
.replit
.config
.local
.cache
*.log
dist
artifacts/mockup-sandbox
attached_assets
screenshots
```

## 3. Шаблон файлов

### 3.1. Dockerfile (pnpm-монорепозиторий)

```dockerfile
FROM node:20-slim AS base
RUN corepack enable && corepack prepare pnpm@9 --activate
WORKDIR /app

# --- Этап установки зависимостей ---
FROM base AS deps
COPY package.json pnpm-workspace.yaml pnpm-lock.yaml ./
# Скопировать package.json каждого пакета из монорепо:
COPY lib/db/package.json lib/db/
COPY lib/api-spec/package.json lib/api-spec/
COPY lib/api-zod/package.json lib/api-zod/
COPY lib/api-client-react/package.json lib/api-client-react/
COPY artifacts/api-server/package.json artifacts/api-server/
COPY artifacts/FRONTEND/package.json artifacts/FRONTEND/
# КРИТИЧНО: только --no-frozen-lockfile!
RUN pnpm install --no-frozen-lockfile

# --- Сборка фронтенда ---
FROM deps AS build-frontend
# КРИТИЧНО: копировать tsconfig!
COPY tsconfig.base.json tsconfig.json ./
COPY lib/ lib/
COPY artifacts/FRONTEND/ artifacts/FRONTEND/
ENV PORT=3000
ENV BASE_PATH=/
ENV NODE_ENV=production
RUN pnpm --filter @workspace/FRONTEND run build

# --- Сборка бэкенда ---
FROM deps AS build-backend
# КРИТИЧНО: копировать tsconfig!
COPY tsconfig.base.json tsconfig.json ./
COPY lib/ lib/
COPY artifacts/api-server/ artifacts/api-server/
RUN pnpm --filter @workspace/api-server run build

# --- Продакшн-образ ---
FROM base AS production
COPY package.json pnpm-workspace.yaml pnpm-lock.yaml ./
COPY lib/db/package.json lib/db/
COPY lib/api-spec/package.json lib/api-spec/
COPY lib/api-zod/package.json lib/api-zod/
COPY lib/api-client-react/package.json lib/api-client-react/
COPY artifacts/api-server/package.json artifacts/api-server/
COPY artifacts/FRONTEND/package.json artifacts/FRONTEND/
# КРИТИЧНО: только --no-frozen-lockfile!
RUN pnpm install --no-frozen-lockfile

# Копировать исходники библиотек (нужны в runtime для Drizzle и т.д.)
COPY lib/db/ lib/db/
COPY lib/api-spec/ lib/api-spec/
COPY lib/api-zod/ lib/api-zod/
# Собранные артефакты
COPY --from=build-backend /app/artifacts/api-server/dist/ artifacts/api-server/dist/
COPY --from=build-frontend /app/artifacts/FRONTEND/dist/public/ artifacts/api-server/dist/public/

ENV NODE_ENV=production
ENV PORT=8080
EXPOSE 8080

# Миграция БД + запуск сервера
CMD ["sh", "-c", "cd lib/db && npx drizzle-kit push --config ./drizzle.config.ts --force && cd /app && node artifacts/api-server/dist/index.mjs"]
```

**Замени `FRONTEND` на реальное имя фронтенд-артефакта** (например, `shift-scheduler`).

### 3.2. amvera.yml

```yaml
meta:
  environment: docker
  toolchain:
    name: docker
    version: "1"

build:
  dockerfile: Dockerfile

run:
  persistenceMount: /data
  containerPort: 8080
```

`containerPort` должен совпадать с `PORT` в Dockerfile и с переменной `PORT` в настройках проекта на Amvera.

## 4. Процедура первого деплоя

### 4.1. Создать файлы
1. Создать `Dockerfile`, `amvera.yml`, `.dockerignore` в корне проекта
2. Убедиться, что `app.ts` раздаёт статику (см. раздел 2.3)

### 4.2. Инициализировать git-репозиторий для деплоя

Деплой выполняется через отдельный git-репозиторий в `/tmp/amvera-deploy`, чтобы не конфликтовать с git Replit.

```javascript
// Выполнять в code_execution
const { execSync } = await import('child_process');
const fs = await import('fs');

const DEPLOY_DIR = '/tmp/amvera-deploy';
const SOURCE_DIR = '/home/runner/workspace';
const AMVERA_LOGIN = 'ЛОГИН';        // заменить
const AMVERA_PASSWORD = 'ПАРОЛЬ';    // заменить
const AMVERA_PROJECT = 'ПРОЕКТ';     // заменить

// Очистить и создать
fs.rmSync(DEPLOY_DIR, { recursive: true, force: true });
fs.mkdirSync(DEPLOY_DIR, { recursive: true });

// Синхронизировать файлы (исключая Replit-артефакты)
execSync(`rsync -av --delete \
  --exclude='node_modules' --exclude='.git' --exclude='.replit' \
  --exclude='.config' --exclude='.local' --exclude='.cache' \
  --exclude='*.log' --exclude='dist' --exclude='artifacts/mockup-sandbox' \
  --exclude='attached_assets' --exclude='screenshots' \
  --exclude='.upm' --exclude='.pythonlibs' --exclude='generated' \
  --exclude='replit.md' --exclude='replit.nix' \
  ${SOURCE_DIR}/ ${DEPLOY_DIR}/`, { encoding: 'utf8' });

// Инициализировать git
execSync(`cd ${DEPLOY_DIR} && \
  git init && \
  git config user.email "deploy@replit.com" && \
  git config user.name "Replit Deploy" && \
  git remote add amvera https://${AMVERA_LOGIN}:${AMVERA_PASSWORD}@git.amvera.ru/${AMVERA_LOGIN}/${AMVERA_PROJECT} && \
  git add -A && \
  git commit -m "Initial deploy" && \
  git push amvera master:master --force`, {
    encoding: 'utf8',
    timeout: 120000
  });

console.log('Деплой отправлен!');
```

### 4.3. Создать скрипт для последующих деплоев

Создать файл `deploy.sh` в корне проекта:

```bash
#!/bin/bash
set -e

DEPLOY_DIR="/tmp/amvera-deploy"
SOURCE_DIR="/home/runner/workspace"

echo "=== Деплой на Amvera ==="

if [ ! -d "$DEPLOY_DIR/.git" ]; then
  echo "Ошибка: репозиторий деплоя не найден. Инициализируйте его сначала."
  exit 1
fi

echo "1. Синхронизация файлов..."
rsync -av --delete \
  --exclude='node_modules' --exclude='.git' --exclude='.replit' \
  --exclude='.config' --exclude='.local' --exclude='.cache' \
  --exclude='*.log' --exclude='dist' --exclude='artifacts/mockup-sandbox' \
  --exclude='attached_assets' --exclude='screenshots' \
  --exclude='.upm' --exclude='.pythonlibs' --exclude='generated' \
  --exclude='replit.md' --exclude='replit.nix' \
  "$SOURCE_DIR/" "$DEPLOY_DIR/"

echo "2. Коммит изменений..."
cd "$DEPLOY_DIR"
git add -A

if git diff --cached --quiet; then
  echo "Нет изменений для деплоя."
  exit 0
fi

COMMIT_MSG="${1:-Обновление $(date '+%Y-%m-%d %H:%M')}"
git commit -m "$COMMIT_MSG"

echo "3. Отправка на Amvera..."
git push amvera master:master --force

echo ""
echo "=== Готово! Сборка запущена на Amvera ==="
```

Сделать исполняемым: `chmod +x deploy.sh`

## 5. Процедура повторного деплоя

После любых изменений в коде на Replit:

**Вариант 1** — через code_execution:
```javascript
const { execSync } = await import('child_process');
execSync('bash /home/runner/workspace/deploy.sh "Описание изменений"', {
  encoding: 'utf8', timeout: 120000
});
```

**Вариант 2** — пользователь сам запускает в Shell:
```bash
bash deploy.sh "Описание изменений"
```

## 6. Если /tmp/amvera-deploy потерян (Replit перезапущен)

Репозиторий в `/tmp` не переживает перезапуск контейнера Replit. Переинициализировать:

```javascript
const { execSync } = await import('child_process');
const fs = await import('fs');

const DEPLOY_DIR = '/tmp/amvera-deploy';
fs.rmSync(DEPLOY_DIR, { recursive: true, force: true });
fs.mkdirSync(DEPLOY_DIR, { recursive: true });

// Синхронизировать файлы (тот же rsync, что в разделе 4.2)
execSync(`rsync -av --delete \
  --exclude='node_modules' --exclude='.git' --exclude='.replit' \
  --exclude='.config' --exclude='.local' --exclude='.cache' \
  --exclude='*.log' --exclude='dist' --exclude='artifacts/mockup-sandbox' \
  --exclude='attached_assets' --exclude='screenshots' \
  --exclude='.upm' --exclude='.pythonlibs' --exclude='generated' \
  --exclude='replit.md' --exclude='replit.nix' \
  /home/runner/workspace/ ${DEPLOY_DIR}/`, { encoding: 'utf8' });

execSync(`cd ${DEPLOY_DIR} && \
  git init && \
  git config user.email "deploy@replit.com" && \
  git config user.name "Replit Deploy" && \
  git remote add amvera https://ЛОГИН:ПАРОЛЬ@git.amvera.ru/ЛОГИН/ПРОЕКТ && \
  git add -A && \
  git commit -m "Re-init deploy"`, { encoding: 'utf8' });

console.log('Репозиторий восстановлен. Запустите deploy.sh');
```

## 7. Типичные ошибки и решения

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` | `--frozen-lockfile` + overrides Replit | Заменить на `--no-frozen-lockfile` |
| `failed to resolve "extends":"../../tsconfig.base.json"` | tsconfig не скопирован в Docker | Добавить `COPY tsconfig.base.json tsconfig.json ./` в build-stage |
| `Server listening` но сайт не открывается | Неверный PORT или не добавлена переменная PORT | Убедиться что `containerPort` в amvera.yml = PORT в env = EXPOSE в Dockerfile |
| Белая страница, API работает | Фронтенд не раздаётся бэкендом | Добавить `express.static` и catch-all route в app.ts |
| `Cannot find module` в runtime | Библиотеки не скопированы в production stage | Убедиться что `COPY lib/db/ lib/db/` и др. в production stage |
| Миграции падают | Нет `DATABASE_URL` в переменных Amvera | Добавить переменную в настройках проекта на Amvera |
| `ECONNREFUSED` к БД | Неверный хост БД | Хост внутри Amvera: `amvera-ЛОГИН-cnpg-ИМЯ_БД-rw` |

## 8. Структура проекта Amvera (PostgreSQL)

При создании БД на Amvera пользователь указывает:
- **Имя БД** (например: `shift-scheduler-sql`)
- **Пользователь** (например: `admin`)
- **Пароль** (например: `156dnpiDNP`)

Внутренний хост формируется автоматически по шаблону:
```
amvera-{ЛОГИН}-cnpg-{ИМЯ_БД}-rw
```

Итоговый `DATABASE_URL`:
```
postgresql://{USER}:{PASSWORD}@amvera-{ЛОГИН}-cnpg-{ИМЯ_БД}-rw:5432/{ИМЯ_БД}
```
